# Troubleshooting

## The GUI looks old or a new tab is missing

Close every running GUI instance and relaunch the intended copy. A Python process keeps the code it loaded when it started.

```powershell
Set-Location W:\Astro\_scripts
P:\python.exe sirilmosaic_gui.py
```

## Cropping Workbench has a blank Master artifact field

Enter the quality report path and click **Load**, or use **Browse** or **Latest**. The report must contain a master paired with an integration-time map. Use a current schema-3 report for the most reliable result.

## Preview Crop appears busy

Large maps are calculated in a worker. The status should move from calculating geometry to rendering previews. If the operation does not finish, inspect the newest `crop_workbench_*.log` and confirm no stale GUI instance is running.

## Create Cropped Master produces no file

Restart the GUI from the current script, confirm the original master and integration-time map exist, and check the crop log for an exit code. The original master is never overwritten; output names contain `_crop_<percent>pct`.

## Verify Run reports a missing manifest or ledger

The report may predate that artifact or the file may have been moved. Use a fresh report generated by the current code. Do not manually invent a manifest or ledger for an old run; treat the warning as part of that run's history.

## Automatic verification artifact is missing

Run Verification is attempted after processing completes. A verification `FAIL`, or an error that prevents verification, returns a nonzero process exit even though completed image artifacts are preserved and the report retains processing status `complete`. Check `verification_status` and `verification_error` in the report, then run `--verify-run` after restoring missing evidence. `--bundle-report` also creates the verification artifact when an older report does not have one.

## Integrity Scan reports duplicates

Duplicates are exact byte-for-byte matches. Decide whether the copies are intentional before stacking. The scan does not delete or move them.

## Integrity Scan says cached

The scan cache is keyed by root/output paths, file relative paths, sizes, modification timestamps, Bayer/orientation settings, drizzle, and scan version. A changed file or setting automatically causes a fresh scan. Delete `integrity_scan_cache.json` only when you want to force a manual refresh.

## Deep Integrity Scan reports a truncated FITS payload

The FITS header declares more image data than the file contains. Treat this as an input failure rather than a harmless metadata warning; recopy the frame from the acquisition source or remove it from the run. The GUI performs this payload check automatically, while the CLI requires `--deep-integrity-scan`.

## Integrity Scan reports dimension groups

Mixed dimensions can be intentional in mosaic data, but they should normally be separated into acquisition cohorts. Review the cohort summary before starting.

## Threshold Replay says metrics are unavailable

Replay requires measured values in a completed frame ledger. A partial run, an older ledger, or a run without usable Siril registration metrics may only provide unknown results.

## Resume Run cannot find a checkpoint

Resume requires `run_checkpoint.json` in the selected output folder. A successful run removes it. Choose the same input/output folders and matching processing settings used by the interrupted run.

Use `Checkpoint Status` or `--checkpoint-status` to inspect referenced reports, manifests, ledgers, staged assignments, and completed products. `Discard Checkpoint` removes only the metadata after confirmation; it does not restore or delete staged files.

If `Abandon Run` reports that manifest sources are missing, it first checks for staged frame/process payloads and an active checkpoint. It will refuse to bypass either. When only manifests and empty staging folders remain and no checkpoint exists, it offers a second confirmation to remove that orphan recovery metadata. The missing entries are recorded in the dialog/status message and are not restored or deleted by this action.

## Resume settings do not match

Resume protects against mixing checkpoints with different seeds, filters, substacks, paths, or processing settings. Reopen the original profile/settings or start a fresh run.

## Resume says an input frame changed

The selected-file manifest records size, modification time, and SHA-256 for new runs. Resume stops before staging when a frame is missing, replaced, reordered, duplicated, or outside the workdir. Restore the original frame or start a new run; do not bypass the check by editing the manifest.

## Resume after force-closing the program says there are no input frames

This should now be handled as a resumable staged run. A hard termination can leave every selected frame under `Lights_sorted` while the original input folder appears empty. Resume uses the checkpoint and staged source manifests to verify those frames before rebuilding staging. If an older copy still reports no supported inputs, relaunch the current operational script and confirm that `run_checkpoint.json` and `Lights_sorted` are both present.

## A run lock already exists

Use `--run-lock-status` to inspect the owner and age. Confirm that no Python or Siril process is still active before using `--break-run-lock`. Cleanup Review deliberately cannot delete an active lock.

## Siril watchdog timeout

The backend stops waiting after the configured open or command timeout, terminates descendant Siril processes, marks the pipe unhealthy, and enters normal source rollback. The command timeout defaults to `0` (no limit) so long-running integrations are not interrupted; set a positive `--siril-command-timeout` when a watchdog is desired. Siril startup has its own timeout and can be adjusted with `--siril-open-timeout`.

## Runtime disk headroom failure

The pipeline checks the work and output volumes after each completed substack. Raise `--minimum-free-disk-gb` only when you have verified the storage plan; lowering it trades recovery safety for continued processing.

## Sources are not where expected

Check the mirrored `rejects` folder and `source_manifest.json`. Do not manually edit `Lights_sorted` or `rejects` while a run is active. Run Verification can identify missing or colliding source paths.

Cleanup Review is deliberately conservative. `Lights_sorted` is always review-only because it may contain source frames during resume, and `rejects` is never offered for deletion. Only selected `.tmp` files, checkpoints, and launcher logs can be deleted after an explicit confirmation.

## Coverage or auto-crop is unavailable

Check for positive `EXPTIME` in every registered frame and matching master/map dimensions. Coverage uses the integration-time map, not the normalized display map.

## Overlap normalization is very slow

This is expected for large smart-scope collections. Disable overlap normalization for thousands of frames; reserve it for smaller dedicated-rig datasets.
